# IEEE Access figure standard for the RCS validation package

This file freezes the graphics conventions used by the project for figures generated from the retained RCS validation and benchmark outputs.

## IEEE requirements adopted

The project follows the official IEEE Access / IEEE Author Center graphics guidance:

- vector output is preferred; PDF is the primary project figure format;
- one-column width is 3.5 in (88.9 mm) and two-column width is 7.16 in (182 mm);
- raster colour/grayscale graphics must exceed 300 dpi and black-and-white line art must exceed 600 dpi;
- Helvetica is used from the IEEE recommended font list, with text targeted at approximately 9–10 pt at final size;
- PDF fonts must be embedded by the output device;
- line graphs must remain interpretable in grayscale by combining colour with line type and point symbol;
- the IEEE Access manuscript is prepared in double-column format.

## Project conventions

- Article numbering is preserved as `Figure_1`, `Figure_2`, and so forth.
- `Figure_1` is the conceptual workflow already maintained with the manuscript and is not regenerated by Gnuplot.
- The reproducible Gnuplot set therefore starts at `Figure_2` and currently runs through `Figure_7`.
- Primary output: vector PDF produced with Gnuplot `pdfcairo`.
- Auxiliary review output: PNG produced with `pngcairo` at 600 dpi using font and line scaling matched to the physical PDF dimensions.
- Figures use a white background, restrained grid lines, Helvetica, no decorative effects, and no global title inside the plotting area. Panel identifiers and matrix headings are retained where they are necessary for interpretation.
- Colour is never the only discriminator. Numeric annotations, different line styles, and different point symbols are used where applicable.
- Scientific-validation figures retain the visual organization already established in the manuscript: faceted matrix headings, percentage labels, compact heatmaps, and uncluttered panel layouts.
- Figures read the canonical CSV tables under `outputs/tables/` directly. No persistent `figure_source` cache is generated.
- Speedup is always computed and plotted against the sequential implementation of the same language family. No cross-language speedup is plotted.
- The horizontal `1x` line marks no acceleration. No diagonal ideal-scaling line is used because the reported estimand is paired sequential-to-parallel speedup, not strong scaling from a parallel one-worker baseline.

| Figure | Scientific role | Canonical source | Generated by Gnuplot |
|---|---|---|---|
| `Figure_1` | Conceptual computational workflow of the governance-aware RCS | Manuscript/model structure | No |
| `Figure_2` | Synthetic validation heatmap | `Table_Synthetic_Validation_Grade_Distribution.csv` | Yes |
| `Figure_3` | Combinatorial distribution of admissible RCS grades | `Table_Combinatorial_Grade_Distribution.csv` | Yes |
| `Figure_4` | Threshold-transition stability by isolated axis and perturbation scenario | `Table_Threshold_Transition_Detail.csv` | Yes |
| `Figure_5` | Updated R sequential scalability: compute and end-to-end elapsed time and per-profile cost | `Table_Benchmark_Runtime_Summary.csv` | Yes |
| `Figure_6` | Within-language parallel scaling at 5,000,000 profiles: R/PSOCK, Cython/OpenMP, and C++/OpenMP | `Table_Benchmark_Within_Language_Speedup_Summary.csv` | Yes |
| `Figure_7` | CUDA acceleration relative only to C++ sequential, separating compute and end-to-end timing | `Table_Benchmark_CUDA_Speedup_Summary.csv` | Yes |

`Figure_7` is retained because the final validated benchmark contains a distinct CUDA result that cannot be represented correctly on the worker/thread x-axis used by `Figure_6`. The manuscript will therefore need to be updated after the figures are validated.

The corrected threshold detail is authoritative for `Figure_4`; in particular, fluid C-to-D contains no reached cases under the retained perturbation scenarios.
