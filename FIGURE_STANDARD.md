# IEEE Access figure standard for the RCS validation package

This file defines the graphics conventions used by the project for figures generated from validated RCS scientific-validation and benchmark tables.

## IEEE requirements adopted

The project follows the IEEE Access / IEEE Author Center graphics guidance already selected for this package:

- vector output is preferred; PDF is the primary project figure format;
- one-column width is 3.5 in (88.9 mm) and two-column width is 7.16 in (182 mm);
- raster colour/grayscale graphics must exceed 300 dpi and black-and-white line art must exceed 600 dpi;
- Helvetica is used from the IEEE recommended font list, with text targeted at approximately 9–10 pt at final size;
- PDF fonts must be embedded by the output device;
- line graphs must remain interpretable in grayscale by combining colour with line type and point symbol;
- the IEEE Access manuscript is prepared in double-column format.

The external guidance links already adopted by the project are retained here:

- https://ieeeaccess.ieee.org/authors/preparing-your-article/
- https://ieeeaccess.ieee.org/authors/submission-guidelines/

## Project conventions

- Article numbering is preserved as `Figure_1`, `Figure_2`, and so forth.
- `Figure_1` is the conceptual workflow maintained with the manuscript and is not regenerated by Gnuplot.
- The reproducible Gnuplot set starts at `Figure_2` and currently runs through `Figure_7`.
- Primary output: vector PDF produced with Gnuplot `pdfcairo`.
- Auxiliary review output: PNG produced with `pngcairo` at 600 dpi using font and line scaling matched to the physical PDF dimensions.
- Figures use a white background, restrained grid lines, Helvetica, no decorative effects, and no global title inside the plotting area.
- Colour is never the only discriminator. Numeric annotations, line styles, point symbols, panel labels, and matrix headings are retained where needed for interpretation.
- Scientific-validation figures preserve compact matrix-specific layouts, percentage labels, heatmaps, and uncluttered panels.
- Plotting scripts read CSV columns by **header name**, not by positional column number.
- No persistent `figure_source` cache is generated.
- No cross-language speedup is plotted.
- The horizontal `1x` line marks no acceleration. No diagonal ideal-scaling line is used because the reported estimand is paired sequential-to-parallel speedup rather than strong scaling from a parallel one-worker baseline.

## Input and output roots

Figures are generated from the `tables/` directory under the selected run root:

```text
local       -> outputs/local/tables/      -> outputs/local/figures/
smoke       -> outputs/smoke/tables/      -> outputs/smoke/figures/
publication -> results/publication/tables/ -> results/publication/figures/
```

`RCS_OUTPUT_ROOT` can redirect both table input and figure output to an isolated root. This is how CI validates the plotting scripts without touching repository result directories.

Publication writes remain protected by `RCS_RUN_SCOPE=publication` and `RCS_ALLOW_PUBLICATION_WRITE=TRUE`.

## Figure mapping

| Figure | Scientific role | Table source | Generated by Gnuplot |
|---|---|---|---|
| `Figure_1` | Conceptual computational workflow of the governance-aware RCS | Manuscript/model structure | No |
| `Figure_2` | Synthetic validation heatmap | `Table_Synthetic_Validation_Grade_Distribution.csv` | Yes |
| `Figure_3` | Combinatorial distribution of admissible RCS grades | `Table_Combinatorial_Grade_Distribution.csv` | Yes |
| `Figure_4` | Threshold-transition stability by isolated axis and perturbation scenario | `Table_Threshold_Transition_Detail.csv` | Yes |
| `Figure_5` | C-reference scoring-kernel runtime: compute and end-to-end elapsed time and per-profile cost | `Table_Benchmark_Runtime_Summary.csv` | Yes |
| `Figure_6` | Within-language parallel scaling at 5,000,000 profiles: R/PSOCK, Cython/OpenMP, and C++/OpenMP | `Table_Benchmark_Within_Language_Speedup_Summary.csv` | Yes |
| `Figure_7` | CUDA acceleration relative only to C++ sequential, separating compute and end-to-end timing | `Table_Benchmark_CUDA_Speedup_Summary.csv` | Yes |

Figure 5 intentionally reports the C computational reference rather than treating R as the reference implementation. Figure 6 is restricted to within-family parallel effects and does not compare languages. Figure 7 remains separate because CUDA has no worker/thread dimension directly comparable with the x-axis used by Figure 6.

## Generation commands

Linux, macOS, or WSL:

```bash
bash scripts/check_figure_requirements.sh
bash scripts/generate_figures.sh
```

Windows:

```bat
scripts\check_figure_requirements.cmd
scripts\generate_figures.cmd
```

Both runners generate PDF and PNG for Figures 2–7 and remove stale generated `Figure_1` artifacts from the selected figure directory.

## CI figure validation

The figure CI does not use retained scientific results. `scripts/create_figure_smoke_fixtures.sh` creates temporary schema fixtures whose only purpose is to validate that the current Gnuplot scripts can consume the current column names and generate Figures 2–7.

These fixtures are explicitly non-scientific and non-publication data. The final figures will be generated only from the validated tables produced by the future final GCP publication run.
